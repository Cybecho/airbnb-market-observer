# 공식 데이터 자동 갱신

## 운영 계약

- 워크플로: **Official data refresh and publish** (`official-data-refresh.yml`).
- 예약: `17 21 * * 0` UTC, **매주 월요일 06:17 Asia/Seoul**. GitHub 예약 실행은 정확한 시각을 보장하지 않으며 지연될 수 있다.
- 실행 환경: GitHub-hosted Ubuntu 24.04, Node 24. 수집 명령은 GitHub Actions Linux가 아니면 거부한다. macOS 설치·빌드·테스트 또는 Codespaces는 사용하지 않는다.
- 비용·인증: 공식 공개 파일과 HTTPS 미리보기 메타데이터만 사용한다. 서비스 API 키·사용자 PAT·브라우저 쿠키·유료 호출이 없다. GitHub가 실행마다 발급하는 기본 `GITHUB_TOKEN`을 쓰며 contents, Pages/OIDC, issues 권한을 별도 job에 제한한다. 따라서 별도의 repository secret을 생성할 필요가 없다.
- 최신 자료와 과거 조사 자료를 분리한다. `checkedAt`는 마지막 성공 확인 시각이지 모든 원천의 관측일이 아니다. 원천별 기간과 갱신일을 함께 읽어야 한다.

## 반영되는 화면과 과거 자료

- 핵심 기회 화면은 자동 갱신된 최신 완결월까지의 당해/전년 1월~동월 생활인구와 최신 도시민박 **공간결합 영업등록 수**를 쓴다. 두 원천의 기간은 다르며 등록 증감·수급 부족 판정이 아니다.
- 기간 평균은 소수 둘째 자리 월평균에 유효일수를 가중한 값이다. 양쪽 연도 모든 달의 04시 유효일이 각 달력 일수와 같은 지역만 비교한다. 윤년은 각 연도의 일수를 사용하므로 과거 원조사의 동일 날짜 쌍 비교와 방법이 다르다. 원조사의 `2026` 명명 열에 다음 연도 값을 덮어쓰지 않는다.
- 생활인구 시계열은 새 완결월을 추가하고 정정분을 대체한다. 신설·대체 동의 과거를 0으로 채우지 않는다.
- 이동·여관 매출은 `extensions.automation` / `public/data/automation.json`에 별도 기간·단위·분모로 제공한다. 상세 구형 조사 탭은 명시된 과거 스냅샷이며 자동으로 최신 자료가 되는 것은 아니다.
- 2025 서울 설문은 연례 보고서·가중치·분모·권리 검토 후 수동 교체한다. KTO 재배포 미확인 값, 민간 유료 지표와 개인 파일은 자동 수집하지 않는다. 월세·전세도 이번 배치 대상이 아니다.
- 지도 경계는 2026-10-01로 고정한다. 새로운 생활인구 행정코드, 경계 변경은 자동 이름 매칭하지 않고 실패·검토로 전환한다. 추정매출의 과거/상권 단위와 현재 행정동이 일치하지 않는 값은 별도 미매칭 수·코드로 남기고 지도에 배분하지 않는다.

## 품질·공개 보호

1. HTTPS 공식 호스트만 허용한다. 원천의 행 수·최신 기간도 HTTPS 공식 미리보기에서 읽고 평문 HTTP로 내려가지 않는다. 인증 헤더·쿠키는 받지 않는다. 요청 횟수·다운로드 크기·재시도·시간을 제한한다.
2. HTTP 200도 ZIP/첨부·파일명·CSV 스키마·인코딩·기간을 검사한다. HTML 오류를 데이터로 쓰지 않는다. 압축 경로·파일 수·해제 크기를 제한한다. CP949 파일은 Linux iconv로 엄격하게 UTF-8 변환하며 잘못된 바이트를 무시하거나 대체하지 않는다. 이동 원천의 문자셋은 OD=엄격한 UTF-8, 목적·수단=CP949→UTF-8 스트림 변환으로 각각 명시하며 대체 문자와 중복 키는 계속 차단한다. 이동 월별 목적·수단 파일을 먼저 검사한 다음 큰 일별 OD 묶음을 처리한다.
3. 모든 날짜·시간 구조, 유일 키, 유효 값, 소스 행 수를 검증한다. `*`·결측·미관측은 0이 아니다. 이동의 동별 관측 날짜가 부족하면 집계는 null이다.
4. 인허가 좌표를 공식 CRS에서 변환하고 점-폴리곤 결합한다. 원천 X/Y의 동/북 순서는 [EPSG:5174](https://epsg.io/5174)의 북/동 축과 반대이므로 [PROJ cs2cs](https://proj.org/en/stable/apps/cs2cs.html)의 `-r` 옵션을 사용하고 Linux 회귀 검사로 확인한다. 경계선·미좌표·미결합을 별도 집계한다. 각 유형 영업등록 공간결합률 95% 미만 또는 전회 대비 급락이면 실패한다. 4종은 중복 가능한 등록이므로 고유 숙소·객실 총수로 합산하지 않는다.
5. 원본 파일은 runner의 `.refresh-private/`에서만 처리하고 삭제한다. 공개 경로와 Actions artifact에는 원본 CSV·주소·전화·개별 사업장·정확한 핀·비밀키를 넣지 않는다.
6. 모든 수집이 통과한 후 후보 JSON을 작성한다. 데이터 재생성·정합성·권리/비밀정보 검사·의존성 보안 검사·수집 전 수집기/앱 단위 테스트·TypeScript 형 검사, 수집 후 데스크톱/모바일/개인파일 회귀를 통과해야 커밋한다.
7. main이 수집 도중 변경되면 커밋을 강제로 덮어쓰지 않고 실패한다. 정상 커밋의 동일 빌드 산출물을 직접 Pages에 배포한다. 기본 토큰의 push가 다른 workflow를 자동 유발할 것이라고 가정하지 않는다.
8. Pages와 동일 concurrency 그룹으로 배포를 직렬화한다. 실패한 빌드는 기존 정상 사이트를 교체하지 않는다. 배포 artifact의 `build-provenance.json`에 실제 검증 데이터 커밋과 실행 ID를 기록한다.

## 저장 파일

- `data/organized/insights/observatory.json`: 월별 생활인구와 정정 검증 정보.
- `data/organized/insights/automation.json`: 최신 자동 집계·원천별 기간·성공 확인 시각.
- `data/organized/insights/refresh-state.json`: 익명 파일 ID·해시·수집기 상태·검증된 이동 집계 캐시. 모두 공개 가능한 집계/메타데이터만 포함.
- `public/data/*`: 결정적 빌더가 재생성하며 파일 크기·SHA-256을 검증한다.
- `.refresh-reports/refresh-report.json`: 집계 건수·원천 기간만 담긴 CI 진단. 7일 보존.

## 실행·복구

GitHub Actions에서 **Official data refresh and publish → Run workflow → main**:

- `refresh`: 실제 확인·수집·검증 후 커밋하고 Pages 배포.
- `check`: 동일 수집·검증·브라우저 회귀를 수행하지만 커밋·배포하지 않음.
- `install`: 최초의 검토된 수집기 설치에만 사용. 기존 파일이 검토 기준과 다르면 덮어쓰지 않고 중단한다. 일상 운영에는 쓰지 않음.

실패하면 자동 생성되는 **[자동 갱신] 공식 데이터 배치 확인 필요** 이슈와 해당 Actions 실행을 확인한다. 같은 상태 이슈를 갱신하고, 다음 정상 수집·배포가 끝나면 자동으로 닫는다. 최초 설치 자체가 실패해 알림 스크립트가 아직 없다면 Actions 실패 기록을 확인한다. GitHub 개인 알림 설정에 따라 이메일/앱 알림 수신 여부는 다를 수 있다.

원천 스키마·코드·권리·분모 변경을 확인한 뒤 코드를 수정하고 `check`, 이어 `refresh`로 검증한다. 단순 네트워크 실패는 기존 데이터를 지우거나 0으로 대체하지 말고 재실행한다. 검증된 이전 커밋의 수동 Pages workflow 재실행이 배포 복구 경로다.

GitHub 공개 저장소의 예약 workflow는 장기 비활성 시 중지될 수 있다. 정상 주간 실행은 실제 원천 확인 시각과 검증 상태를 커밋하지만, 실패가 장기간 지속되면 예약 활성 상태도 직접 점검해야 한다. 외부 유료 모니터링이나 사용자 컴퓨터의 상시 실행에는 의존하지 않는다.

## 실행·개인정보 검증 경계

- 수집 진입점은 Linux, `GITHUB_ACTIONS=true`, `RUNNER_ENVIRONMENT=github-hosted`를 함께 확인한다. 워크플로도 `ubuntu-24.04`에 고정한다. `RUNNER_ENVIRONMENT`는 [GitHub 공식 기본 환경변수](https://docs.github.com/en/actions/reference/workflows-and-actions/variables)이며 self-hosted 실행을 구분한다.
- 이 검사는 실수로 로컬·self-hosted에서 실행하는 것을 막는 운영 보호장치다. 환경변수만으로 악의적 위조에 대한 암호학적 호스트 증명을 제공하지 않는다. 실제 실행 위치는 GitHub Actions의 실행·runner 기록으로 확인한다.
- 개인정보 방어는 명시적 집계 출력 구조, 원본 비공개·임시 삭제, 금지 필드 및 일부 민감 문자열 검사를 함께 사용한다. 정규식은 일반적인 개인정보 탐지기가 아니며, 신규 원천·출력 필드를 추가할 때 별도 코드·권리 검토가 필요하다.
- 수집 전 통합 회귀 검사는 실제 집계 함수의 반환 구조, 인허가 `csvSha256` 필드, 정확 코드 집합, 0과 결측 구분 및 금지 필드 거부를 확인한다. 테스트 데이터는 합성 값이며 실제 관측치가 아니다.
