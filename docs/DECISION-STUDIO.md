# 기회 · 적합 · 검증

## 목적과 범위

대화에서 추론한 핵심 목적을 세 단어로 압축했다. 이는 확정된 사용자 분류가 아니라 이번 작업의 설계 가설이다.

1. **기회**: 현장조사를 집중할 동을 좁힌다.
2. **적합**: 일행 규모별 관측 프로필에서 객실 구성에 관해 확인할 질문을 만든다.
3. **검증**: 매출의 평균·중앙값과 연결 가능한 단위를 확인한다.

월세·전세·수익률·순이익은 이 흐름에서 제외한다. 기존 임대차 자료를 삭제하거나 매출과 결합하지 않는다. 기존 지도·시계열·원자료와 상세 근거는 보존하고 주 탐색은 핵심 판단·지도·지역 비교·데이터 연결로 좁혔다.

## 차트 선택

검토 대상: ECharts, D3, Vega-Lite, Observable Plot, React Flow, Mermaid, Cytoscape.js, Plotly.js.

행정동 지도는 Leaflet, 산점도와 평균·중앙값 비교는 ECharts SVG를 사용한다. 월별 생활인구는 필요한 Chart.js 구성요소만 지연 로드한다. 등록 수의 로그 눈금은 D3의 d3-scale만 사용하며 0 자리는 별도로 표시한다. 고객 프로필은 작은 SVG 구간을 정렬한 매트릭스로 구현한다. React Flow/Mermaid/Cytoscape의 관계도가 필요한 실제 연결 자료는 없다. 국적→동네→숙소→매출 Sankey, 가상의 고객 여정, 종합 점수·투자 순위는 만들지 않는다.

도표 오른쪽의 **읽는 법**은 마우스를 올리거나 키보드로 포커스하면 열리고, 터치로 고정·해제할 수 있다. Esc와 바깥 클릭으로 닫는다. 데이터 파일은 도표 숫자를 제공할 뿐, 탐색 목적지·HTML·명령 실행을 지정할 수 없다. 색 외에 점 모양과 선 종류를 함께 쓰고 원값 표를 유지한다. [참고한 다섯 자료와 표시 조건](../THIRD_PARTY_NOTICES.md#화면과-차트)

## 1. 기회: 변화 × 등록 수준

- 공식 갱신 자료가 있으면 검증한 기간·등록 관측일을 사용한다. 형식이 잘못된 공식 자료를 과거 값으로 대체하지 않는다. 공식 갱신 자료가 없는 초기 배포의 입력: `rows`의 `foreign_yoy_mean_2026_04`, `foreign_yoy_yoy_pct_04`, `foreigner_operating_spatial`, `presence_comparison_valid_304days`.
- 비교 유효 플래그가 명시적으로 true인 동만 포함한다. 존재값·등록값·변화율의 결측이나 부적절한 값은 제외한다. 등록 0개와 존재 0명은 실제 값으로 유지한다. 중복 행정동 코드는 해당 코드 전부를 제외한다.
- 세로축은 공식 완료월까지 두 해 같은 기간의 04시 생활인구 변화율이다. 초기 기준은 2025·2026년 1~10월이다. 통신 기반 존재 추정은 숙박객이나 예약 수가 아니다.
- 가로축은 인허가 스냅샷의 영업등록 수준이다. 같은 기간의 공급 변화가 아니며 Airbnb 활성 숙소 전수도 아니다.
- 등록 중앙값은 비교 가능한 서울 전체 동 기준으로 고정한다. 구나 최소 존재인구 필터를 바꿔도 기준을 재계산하지 않는다. 중앙값 이하·초과를 상대적 저등록·고등록으로 분류하며, 증가 0%는 비증가에 포함한다.
- 등록 축은 로그 간격이다. 실제 0개는 0.5라는 별도 그리기 좌표에 배치하고 0으로 표기한다. 원자료·툴팁·표의 0개를 바꾸지 않는다.
- 중심 보기는 -50~50%다. 범위 밖 값은 경계 삼각형으로 표시하며 원값·제외 수와 전체 범위 전환을 제공한다. 범위 밖 값을 통계에서 삭제하지 않는다.
- 점 또는 접근 가능한 원값 표에서 선택하고, 지도·24개월 추세·최대 4동 비교로 이동한다. 순위 대신 조건을 제공한다.

## 2. 적합: 일행 규모별 프로필 매트릭스

- 2025 서울 전체 공유숙박 이용자 설문이다. 행정동을 선택해도 지역별 프로필로 바뀌지 않는다.
- 구성비와 공유숙박일수: 공유숙박 이용자 N=746. 구성비는 가중치 합이 분모이고, 숙박일수는 각 일행 규모의 유효값 가중 중앙값이다. 항목별 유효·결측 N을 표시한다.
- 1인·공유숙박 1박 지출: 공유숙박만 이용한 `shared_only` N=647, 지출 유효 N=640. 이 별도 유효표본의 가중 P25·중앙값·P75를 표시한다.
- IQR은 가운데 50% 분포이며 신뢰구간이 아니다. 모든 일행 행은 같은 금액 축을 사용한다. 분위수가 없거나 순서가 뒤집혔으면 구간을 그리지 않는다.
- 결측과 0원을 구분한다. 일행 구성비·숙박일수·지출을 서로 곱하지 않는다. 일행 규모로 가족 여부·객실 수·허용 정원을 추론하지 않는다.
- 1인 숙박지출을 공유숙박 박수로 나눈 값은 객실 ADR·숙소 매출이 아니다. 일행 수를 곱해 객실가격을 만들지 않는다.
- 행 선택은 해당 표본과 현장 질문을 강조한다. 적합도 점수나 지역 고객 예측은 생성하지 않는다.

## 3. 검증: 침실별 평균·중앙값

### 기존 시장 집계

`extensions.revenue.bedrooms`를 기간·범위·출처 URL이 같은 그룹으로 나눈다. 여러 그룹은 선택해서 하나씩 본다. 연간 값은 KRW/년 단위를 유지한다. 공급업체 보고 숙소 수를 매출 유효표본 N으로 오인하지 않게 표시한다. 중복 침실 집계는 재평균하지 않고 제외한다. 비공개 값은 null이며 0원이 아니다.

### 브라우저 로컬 숙소·월

`amo-overlay/1`의 `listings.listingId`와 `listingMonthly.listingId`가 정확히 일치한 경우에만 침실 수와 매출을 연결한다. 한 달씩 비교하며 관측된 고유 숙소만 N에 포함한다. 기간을 합치거나 연환산하지 않는다. 실제 0원은 포함하고 결측·잘못된 값은 제외한다. 중복 ID가 생기면 관련 행 모두를 제외한다.

선택 동 필터는 명시적 8자리 코드가 일치한 숙소에만 적용한다. 도시 집계만 있는 `marketMonthly`로 침실 매출을 만들지 않는다. 출처의 매출 정의를 유지하고 실제 정산인지 임의로 단정하지 않는다. 전용면적·건축물 용도·고객↔예약은 자료가 없어 미연결로 표시한다.

## 개인정보·공개 경계

공개 데이터 payload는 변경하지 않는다. 개인 파일은 사용자가 연결한 브라우저 메모리에서만 쓰며 localStorage, IndexedDB, 네트워크 업로드를 추가하지 않는다. 새 테스트에는 합성 자료만 포함한다. 화면에 표시되는 조사 순서는 실제 고객 이동이나 인과관계가 아니다.

## 검증

로컬 설치·빌드·테스트를 하지 않는다. GitHub-hosted Linux에서 기존 데이터 검사·공개 경로 검사·의존성 감사·단위 테스트·빌드·브라우저 테스트를 통과해야 소스 반영과 Pages 배포를 진행한다.

추가 단위 검증: null/0, 동기간 유효성, 기준 고정, 잘못된 코드·수치, 시각 범위와 원값 보존, 일행 범주, 정확한 숙소 ID/동 코드, 단일 월, 중복 제외.
추가 브라우저 검증: 세 단계 전환, 서울 설문 분모 유지, 공개 잠금 상태, 숙소·월 로컬 연결, 브라우저 메모리 초기화, 모바일 폭과 탐색 유지.
