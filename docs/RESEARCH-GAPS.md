# 공개 근거·결측 원장

이 문서는 서울 25구를 같은 기준으로 보는 공개판의 한계를 설명한다. 새 수집, 원격 질의, 스크래핑, 개인기록 사용을 하지 않는다. 현재 입력은 이미 수집·공개 가능한 무료 자료뿐이다.

## 먼저 구분할 것

| 상태 | 뜻 | 이 공개판에서 하는 일 |
|---|---|---|
| 현재 공개 관측 | 이미 수집한 공개 집계로 직접 읽을 수 있음 | 기간·단위·분모를 보존해 표시 |
| 무료 검증 경로 | 공개 원본에서 범위·상태를 확인할 수 있음 | 미래 결과를 이미 얻은 것처럼 쓰지 않음 |
| 동의·권한 필요 | 소유자 또는 권한 계정의 자료가 필요함 | 개인·주소·정산 원장을 공개 입력으로 받지 않음 |
| 원천 미제공·보류 | 현재 지원되는 교차 원천이 없음 | 0, 프록시, 곱셈으로 메우지 않음 |

## 네 가지 핵심 질문

### 1. 실제 투숙은 얼마인가: 예약·차단·판매가능 박수

- **현재 공개 관측:** [단기체류 외국인 생활인구](https://data.seoul.go.kr/dataList/OA-23018/S/1/datasetView.do)는 행정동·시각별 추정 체류 인원, [외국인 OD](https://data.seoul.go.kr/dataList/OA-22379/S/1/datasetView.do)는 반복 이동 이벤트다. 둘 다 guest-night, 예약, 점유율이 아니다.
- **빠진 것/이유:** 숙소·날짜별 예약완료 박수, 실제 체크인 인원·박수, 노쇼, 호스트 차단, 판매가능 총박수. 예약/점유 박수만으로는 실제 투숙 인원수나 노쇼를 알 수 없고, 공개 등록·운영 기록만으로도 실제 사람 수를 알 수 없다.
- **어디서/어떻게:** 소유자 또는 권한 있는 PMS·OTA 계정이 숙소 ID·날짜별 booked/blocked/sellable 정의의 달력과 실제 체크인 인원·노쇼 구분 기록을 동의 범위에서 제공한다. blocked·판매중지일을 예약으로 변환하지 않는다.
- **키·기간·분모:** 숙소×일. 예약률 분모는 정의된 sellable nights이며, 실제 guest-night은 체크인 인원×실제 숙박일이다. unavailable 사유를 별도 열로 유지한다.
- **확보 시 가능한 결론:** 같은 정의·기간에서 예약률·차단 사유와 실제 guest-night을 별도로 기술할 수 있다.

### 2. 고객은 누구인가: 거주지·국적·동·객실

- **현재 공개 관측:** [STO/Consumer Insight 2025 최종 설문](https://sto.or.kr/survey/16119)의 서울 공유숙박 이용 설문은 서울 전체의 가중 집계(n=746)다. 거주국은 국적이 아니며, 동·객실별 실제 고객명부가 아니다.
- **빠진 것/이유:** 국적×동/객실×숙박업의 교차표와 실제 투숙객 분모. 공개 단기외국인 자료는 숙소 객실에 연결되지 않는다.
- **어디서/어떻게:** 현재 지원되는 공개 교차 원천은 없다. 동일 표본틀·정의·허가 조건을 가진 기관의 비식별 교차 집계가 공개될 때만 원표의 분모와 억제 기준을 확인한다.
- **가능한 결론:** 지금은 서울 전체 공유숙박 이용자의 거주지역 구성만 말할 수 있다. 국적 타기팅이나 동·객실 고객 비율은 보류한다.

### 3. 공급은 실제로 얼마나 활성인가: 인허가·주소·경계

- **현재 공개 관측:** [외국인관광도시민박업](https://data.seoul.go.kr/dataList/OA-16045/S/1/datasetView.do) 등 등록 상태 스냅샷을 현재 지도에서 행정동 경계에 지오조인한 업종별 인허가 건수로 읽는다. 경계 판본(기준시점)과 미연결 여부를 함께 남긴다.
- **무료 검증 경로:** 원본 페이지에서 상태·기록일을 확인하고, 공식 코드·경계 판본(기준시점) 및 미연결 점검 결과를 보존한다. 관할 구청에는 현장 사실과 허가 범위를 문의할 수 있으나, 이 절차가 법률판단을 제공하지는 않는다.
- **빠진 것/이유:** 실제 영업 중인 객실 공급·플랫폼 활성 매물과 주소 단위의 검증 가능한 경계 연결. 운영·인허가 기록은 허가/상태 기록일 뿐 실제 객실 수·플랫폼 매물 수·실제 투숙 인원 수가 아니며, 법정동과 행정동은 다르다.
- **가능한 결론:** 25구/행정동의 등록 기록 배경은 가능하다. 실제 객실 공급, 플랫폼 공급, 법적 적합성, 공급 부족은 결론내리지 않는다.

### 4. 수익성은 얼마인가: 정산·침실·면적·비용

- **현재 공개 관측:** [서울 전월세 실거래](https://data.seoul.go.kr/dataList/OA-21276/S/1/datasetView.do)는 자치구×유형 계약 배경이다. [서울 추정매출](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)의 여관 매출은 선택한 자료의 최신 공개분기 카드기반 업종 추정치다. 2026년 2분기는 고정된 역사적 관측 예시일 뿐 현재값으로 취급하지 않는다.
- **빠진 것/이유:** 실제 호스트 정산, 청소·관리·공과금·수수료, 숙소 ID와 침실·면적·정확한 지역의 연결키. 여관 카드매출은 Airbnb 매출이 아니며 침실군은 면적·등록객실·건물장부와 같은 단위가 아니다.
- **어디서/어떻게:** 소유자가 월별 settlement·비용 원장·숙소 ID·침실·면적·행정구역을 제공하고 기간·통화·세금 포함 여부를 명시한다. 주소·개인정보는 공개하지 않는다.
- **키·기간·분모:** 숙소×월. 총액/순액, 비용 항목, 침실 정의, 전용·계약면적을 분리한다.
- **가능한 결론:** 동일 기간·동일 숙소 단위의 침실/면적/지역별 실현 정산과 비용 분포는 기술할 수 있다. 공개 임대차나 여관 카드매출에서 이를 역산하지 않는다.

## 이동은 숙박의 프록시일 뿐

생활인구는 행정동×월의 04시/14시 추정 인원, OD는 선택한 자료의 최신 공개월 일유형별 반복 이동 이벤트다. 고정 과거월은 역사적 관측 예시로만 표시한다. 유효일수와 경계 주석을 유지해 지역 배경과 변화는 비교할 수 있다. 이를 고유 관광객, 여행, 숙박박수, 예약률, 점유율로 변환하지 않는다.

## 여관 카드매출과 Airbnb를 섞지 않기

[서울 추정매출](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)은 선택한 자료의 최신 공개분기에 해당하는 여관 업종 카드기반 추정매출이다. 2026년 2분기처럼 고정 과거분기는 역사적 관측 예시일 뿐 현재값이 아니다. 동별 숙박업 경제 배경으로만 사용한다. Airbnb listing/host settlement의 분모가 아니므로 Airbnb 매출·ADR·점유율·호스트 수익으로 이름을 바꾸지 않는다.

## 권리와 비공개 경계

- 이미 수집한 공개 관측의 원본 링크·기간·집계 단위는 보인다. [외국인 방문 목적(OA-22378)](https://data.seoul.go.kr/dataList/OA-22378/S/1/datasetView.do)은 관광 외 목적도 포함하며, [외국인 교통(OA-22656)](https://data.seoul.go.kr/dataList/OA-22656/S/1/datasetView.do)은 자체 도착 추정 분모를 유지한다. KTO DataLab은 권리 확인 대기·공개판 제외 상태라 숫자를 싣지 않는다. 라이선스와 재배포 범위는 `DATA_LICENSES.md` 및 `docs/data/ATTRIBUTION.md`를 따른다.
- 실제 Airbnb 정산, 예약 달력, 정확한 주소·연락처, 응답자·계약자 행은 공개 입력값이 아니다.
- AirDNA, Airbtics, AirROI, 공유숙박맵은 민간 자료다. 무료/공개라고 주장하지 않으며 수치, 스크린샷, 체계적 순위를 재배포하지 않는다.
- 공공 원자료 재확인 경로는 이미 결과가 확보됐다는 뜻이 아니다. 민간/개인 데이터의 동의나 재배포 권한도 자동으로 생기지 않는다.
